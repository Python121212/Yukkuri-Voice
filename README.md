# Yukkuri Voice

「ゆっくり」専用の音声合成（TTS）エンジンを、既存エンジンに頼らずスクラッチから作るプロジェクト。
エンジン本体は **依存ゼロの C99**、Android アプリは **Kotlin + JNI** のネイティブ実装。

- 方式: **フォルマント合成**（ソース・フィルタ型）— 学習データ不要、CPU だけで動く
- 声: **プリセット方式**（ピッチ / フォルマント / 話速 / 抑揚 / 息 / ビブラート）
- 入力: **漢字かな交じり文**（8MB の読み辞書を同梱、最長一致でカナ化）
- 出力: **APK**（GitHub Actions で自動ビルド）

サンプル音声は `docs/audio/` にあります（`demo_yukkuri.wav` など）。
作り直すときは `sh scripts/gen-audio.sh`（読み上げ内容はこのスクリプトの表が唯一の定義）。

## すぐ試す（APK）

GitHub Actions が `main` 以外のこの作業ブランチへの push ごとに APK をビルドし、
リリース `apk-latest` に上書きアップロードします。

**[app-debug.apk をダウンロード](https://github.com/Python121212/Yukkuri-Voice/releases/download/apk-latest/app-debug.apk)**

1. Android 端末で上記リンクを開く（「提供元不明のアプリ」の許可が必要）
2. インストールして起動
3. 文章を入力 →「ゆっくり話す」

> debug 署名なので、Play ストア配布用には release 署名の設定が必要です。

```
  src/presets.c         声のプリセット

  src/main/java/com/py1212/yukkuri/
    MainActivity.kt       UI・再生（AudioTrack）・WAV 保存
    NativeEngine.kt       JNI ラッパー

.github/workflows/     APK ビルド + エンジンテスト + リリース添付
```

## エンジンのしくみ

1. **読み変換**（Kotlin）
   漢字かな交じり文を、同梱辞書（約 25 万語）の最長一致でカタカナに変換。
   数字は桁読み（`1234` → `センニヒャクサンジュウヨン`）、記号・絵文字は読み飛ばし。

2. **発話プラン**（`plan.c`）
   かな列を音素列に展開し、モーラごとの F0（抑揚）と長さを決める。
   促音「っ」は次の破裂音の閉鎖を伸ばし、長音「ー」は直前の母音を伸ばす。
   母音が連続する箇所には軽い声門破裂を入れる。

3. **合成**（`synth.c`）
   - 声帯パルス: Rosenberg パルスの微分（-12dB/oct の自然な傾斜）+ ジッタ + ビブラート
   - 8 段の 2 次共振器（F1–F8）をカスケード。5 段で打ち切ると 4kHz 以上が
     -60dB/oct で落ちて「こもる」ので、F6–F8（幅の広い高域フォルマント）まで継ぐ
   - 高域の残りの落ち込みは 3kHz 以上のシェルフで補正（声帯音源の -12dB/oct を打ち消す）
   - 摩擦音は帯域ノイズ（`/s/` は 5–6kHz、`/sh/` は 3kHz 付近）を別経路で作り、
     母音のピークに対して一定の相対レベルで混ぜる
   - 破裂音は無音の閉鎖 → 数 ms のノイズバースト（1-2ms の立ち上がり付き・2 次 LP で 3.5kHz 上限）
   - 唇の放射特性（+6dB/oct 相当の傾斜）
   - 有声フレームの RMS を基準にした自動音量補正 + AGC + 包絡追従型ピークリミッタ

### 音響設計の要点

- **フォルマントの帯域幅は F0 より広く取る**（`bw_for()`）。
  帯域幅が F0（この声で 280Hz）より狭いと、高調波がフォルマントの山を
  「飛び越えて」しまい、母音が聞き分けられなくなる。F1 の帯域幅は
  F0×1.15 を下限にしている。
- **破裂のローパスはバースト専用にする**。前回、ノイズ経路全体に 3.5kHz の
  LP を掛けたら摩擦音の /s/（5-7kHz）まで削れて「し」「す」「さ」が
  ぼやけた。バーストは専用の LP（3.2kHz）、摩擦音は 6kHz の LP にする。
- **破裂音のバーストは 1-4kHz に収め、立ち上がりを付ける**。
  高域まで通すと「プシュ」、いきなり最大振幅から始めると「プッ」という
  クリックに聞こえる。閉鎖中はノイズ経路の状態（放射の前回値・帯域フィルタ）も
  落とす。残すと閉鎖明けの 1 サンプルが跳ねる。
- **有音の切れ目には必ず減衰を入れる**。語尾や休止の直前を 60ms で
  コサイン減衰させないと、波形が最大振幅のまま 0 になって「プツ」と切れる。
- **帯域ノイズは共振器の雑音利得で正規化する**。2 次共振器は帯域幅が狭いほど
  白色雑音の出力 rms が下がる。補正しないと「し」を狭くしたときにノイズだけ
  15dB 落ちて子音が消える。`reson_run_norm()` で帯域幅によらず一定にする。
- **抑揚は 2 モーラ周期 + 全体の下降 + 文末の下降の 3 つを重ねる**。
  どれか 1 つだと平板に聞こえてロボットになる (F0 の標準偏差 3.8Hz → 13.3Hz)。
- **摩擦音の帯域は狭く、長さも短く**。「し」(/ɕ/) のノイズ帯域を 1800Hz 幅で
  取ると /s/ に近づき「す」に聞こえる。900Hz 幅・78ms にすると
  3-4kHz と 5-6kHz のコントラストが +9.7dB になり区別できる。
- **閉鎖中も声帯パルスの位相を進める**。止めておくと閉鎖明けの 1 サンプル目で
  位相が飛び、その段差が「プツ」というクリックになる。あわせて破裂音・
  声門破裂の本体先頭に 4ms の立ち上がりを付ける。
- **摩擦音は母音より 12dB 下にする**。母音と同じ音量だと、母音に入る瞬間に
  ノイズが止まって「シュ」と切れて聞こえる。/s/ は放射特性で /ɕ/ より
  大きくなるので、中心周波数に応じて補正する。
- **AudioTrack は書き込み直後に stop しない**。バッファ (最大 250ms) に
  残った末尾が捨てられ、語尾が「プツ」と切れる。再生位置が追いつくまで
  無音を流してから止める。
- **音量正規化は有声区間だけで行う**。摩擦音はもともと平らなスペクトルを
  持つので、全体で正規化するとサ行だけが突出して耳障りになる。
- 目標スペクトル（400–700Hz を 0dB とした LTAS）:
  1–2kHz −10dB / 2–3kHz −14dB / 3–4.5kHz −18dB / 4.5–7kHz −22dB。
  `tools/ltas.py` で確認できます。

フォルマント値は `core/src/internal.h` の母音表と `core/src/phones.c` の音素表で管理しています。
「もっとゆっくり」「もっと高く」は `presets.c` のプリセットを編集するだけで作れます。

## 開発

```bash
# エンジンをホストの gcc でビルドして WAV を作る
gcc -std=c99 -O2 -Icore/include core/src/*.c tools/cli.c -lm -o ykcli
./ykcli "ゆっくりしていってね。今日はいい天気ですね。" out.wav yukkuri --dump

# エンジンのテスト
gcc -std=c99 -O2 -Icore/include core/src/*.c tools/test_engine.c -lm -o test_engine
./test_engine

# 読み辞書の再生成（kuromoji が必要）
npm install && npm run dict

# APK は CI でビルド（ローカルに Android SDK があれば）
gradle :app:assembleDebug
```

分析用スクリプト（要 numpy）:
`tools/ltas.py`（帯域ごとの長時間平均スペクトル。**これが一番信頼できる**）、
`tools/formant.py`（LPC でフォルマント推定。実装が素朴なので参考程度）、
`tools/spectrum.py`（1/3 オクターブ表示）。
